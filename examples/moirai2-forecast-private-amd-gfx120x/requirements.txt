# --- The SDK (this example's own runtime deps) -----------------------------
# main.py calls the workload over HTTP, so it needs the SDK + requests.
#
# local, unpublished build — see ../CONTRIBUTING.md#4-depending-on-the-sdk:
#   ( cd ../../bindings/python && maturin develop --release )
# or, once published:
#   inferencekey>=0.1.0
requests>=2.28

# --- The custom backend's deps (installed into the backend's venv) ---------
# The SDK runtime that serves the backend imports NONE of these — they belong
# to backend.py (moirai2). The worker installs them into the backend's venv
# from this file (name = "moirai2", requirements = "requirements.txt").
#
# CPU-only backend (see the packaged manifest's `cpu_only`): uni2ts pins an
# older stack (`torch>=2.1,<2.5`, `scipy~=1.11.3`) that has NO wheels for the
# node's ROCm torch or for CPython 3.13 — so a GPU/py3.13 install is
# unresolvable. Instead this backend runs on **CPU under CPython 3.12** (declared
# via requires_python), where uni2ts installs cleanly with its own pinned deps
# (including a CPU torch). Moirai 2.0 R-small is tiny, so CPU inference is fine.

# The InferenceKey SDK runtime provides `inferencekey.backend.serve`, which the
# worker launches inside the backend venv; keep it resolvable from site-packages.
inferencekey==0.260708.1124

# Moirai 2.0 (uni2ts) is only published from GitHub. Installed with its own deps
# (torch CPU, gluonts, scipy, einops, …) — no torch pinning games needed on CPU.
uni2ts @ git+https://github.com/SalesforceAIResearch/uni2ts.git
